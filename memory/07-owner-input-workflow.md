# Owner Input Workflow

Use this file when the owner is ready to answer the remaining public-site blockers.

## Meeting Pages

Open these in order:

1. `/owner-review-prep`
2. `/owner-walkthrough`
3. `/owner-input-packet`
4. `/owner-review-worksheet`
5. `/owner-answer-log`
6. `/post-meeting-update-plan`
7. `/approval-matrix`
8. `/next-actions`

## What To Collect

Capture owner answers for:

- founder/origin story
- public category wording
- first cohort audience, age range, schedule, location stance, and capacity
- price, membership, donation, or scholarship stance
- day-one spaces versus future-only spaces
- childcare, cafe, Foxtail, rentals, teen work, and Wilds public stance
- teen contribution and supervision boundaries
- interest form fields, owner follow-up, and privacy language
- proof assets, photos, testimonials, credentials, and permissions
- public call to action

## Status Marks

Use the worksheet statuses this way:

- Approved: update the approval matrix, then draft copy.
- Revise: keep the item private and rewrite the question or recommendation.
- Hold: leave the site as private planning only.
- Validate: add an action item before public copy changes.

## Update Order

After the meeting, update files in this order:

1. `memory/08-owner-answer-log.md` with the answer, status, date, and next update.
2. `app.py` data lists for approvals, decisions, assumptions, draft copy, and action items.
3. Route templates only after the data model has the approved wording.
4. `memory/02-site-strategy.md` with the new current recommendation.
5. `memory/04-route-architecture.md` only if routes or data ownership changed.
6. `memory/05-owner-preview-rules.md` if a new rule or boundary emerged.
7. Tests for any new route, approved text, or changed claim boundary.

## Guardrail

Owner answers are not automatically public copy. They become public-ready only after the answer log records the owner decision, the approval matrix marks the claim ready, and the draft page no longer depends on unresolved launch, pricing, intake, operational, or privacy details.
